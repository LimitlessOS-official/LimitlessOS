# LimitlessOS Roadmap

## Current Gate: M10 User Authentication and Login

M1 cleanup-final through M9 bare-metal validation are accepted. M10 adds a UEFI Product login gate, first-run single-user setup, bcrypt-hashed persistent user record, and session lock/unlock. It is not multiuser account management, not PAM/LDAP/remote auth, not an app store, not auto-update, not live public update fetching, and not real internal-disk install/write work.

Product profile:

- Build command: `.\tools\build.ps1 -Architecture x86_64 -BuildProfile Product`
- BIOS kernel: `KERNEL64-BIOS.BIN`, 456800 bytes, 893 / 1024 BIOS sectors, 131 reserve, checksum recorded in the generated artifact inventory
- UEFI kernel: `KERNEL64.BIN`, 551072 / 2097152 bytes, with the current checksum recorded in the generated artifact inventory and verified against BOOTMAN.TXT byte count/checksum, with no UEFI sector arithmetic
- Sector status: ok for BIOS fallback; UEFI governed by the 2 MiB file contract
- Product apps: APPEND, CAT, COPY, DELETE, LS, MKDIR, MOVE, RENAME, STAT, TOUCH, WRITE
- Product UEFI builtins: apps, help, hwval, info, lock, net, pkginfo, pwd; BIOS fallback omits `lock` and reports login/session lock unavailable
- Product GUI apps: Terminal, File Manager, Settings
- Product services: policy/security broker, console/shell broker, input broker, display/compositor, window manager/desktop shell, filesystem broker, block/storage broker, hardware inventory broker, network broker, installer dry-run service/tool, settings/system-info provider
- Product session: one authenticated local console session; no full multiuser account-management UI, password-change UI, PAM/LDAP, or remote auth yet
- Product package behavior: UEFI Product verifies Ed25519-signed package archive and payload signatures, denies missing/invalid/wrong-key/tampered/checksum-mismatched/malformed/oversized/duplicate/downgrade package data, requires scoped install authority, denies denied-capability requests, verifies signed update-index fixtures with unsigned/tampered/wrong-key/rollback/replay/no-auto-install coverage, and exposes read-only trust state through Settings and `pkginfo`
- Product behavior: x86_64 boot, UEFI ISO/disk verification, UEFI login/first-run setup/lock/unlock, persistent ring-3 shell, truthful help/apps/pkginfo/hwval output, brokered persistent file workflow, hardware-gated brokered network status, brokered interactive desktop, focused-window keyboard routing, NVMe persistence verification, service/session status, signed package admission, package trust visibility, read-only hardware validation, capability denial checks, no ambient authority

Current bootstrap status:

- IDT, PIC remap, PIT timer ticks, syscall dispatch, paging, and a small physical frame allocator are now in the codebase.
- IPC currently exists as a bootstrap endpoint and queue model for early service bring-up.
- A cooperative bootstrap scheduler and service supervisor are now online for `init`, driver-host, telemetry, and AI-policy broker services.
- Service identity and capability-gated IPC enforcement are now online for bootstrap services.
- A first ring-3 userspace runtime now runs through a TSS-backed privilege transition and exercises syscalls from user mode.
- Separate bootstrap user address spaces and cooperative user-task switching are now online.
- Timer-preemptive bootstrap user-task switching is now online through the PIT IRQ path.
- Blocking user sleep syscalls, kernel idle fallback, and timer wakeups are now online for bootstrap processes.
- Event-driven service wait/wake behavior and IPC-triggered endpoint wakeups are now online for bootstrap services.
- Kernel-managed user mailbox replies and blocking wait syscalls are now online for bootstrap ring-3 processes.
- Bounded direct user-to-user mailbox sends with per-endpoint sender rules are now online for bootstrap ring-3 processes.
- Explicit user endpoint registration with sender masks is now online for bootstrap ring-3 processes.
- Owner-and-role lookup for registered user endpoints is now online for bootstrap ring-3 processes.
- Bounded copied-payload user IPC buffers are now online for bootstrap ring-3 processes, replacing the earlier register-pair-only message path.
- Kernel-namespaced service endpoint discovery is now online for bootstrap services and ring-3 clients, replacing hard-coded policy broker routing in the proof path.
- Process-scoped send capability handles are now online for bootstrap ring-3 IPC, replacing raw destination endpoint IDs in the user-facing send path.
- Explicit capability revocation with stale-handle rejection is now online for bootstrap ring-3 IPC.
- User-published endpoint-class registration and class-based lookup are now online for bootstrap ring-3 IPC, so peer discovery no longer depends on hard-coded owner IDs in the direct-send path.
- First-pass capability delegation is now online for bootstrap ring-3 IPC, allowing one process to grant a narrower send right to another through kernel-mediated delivery.
- Capability provenance and attenuation are now online for bootstrap ring-3 IPC: lookup-issued handles can delegate, delegated handles are reduced to send-only rights, and second-hop delegation attempts are rejected.
- Delegation policy controls are now online for bootstrap IPC: services and user endpoints can be marked non-delegable, and the kernel rejects delegation attempts even when the caller still holds a delegable-looking handle.
- Lease-based capability expiration is now online for delegated bootstrap ring-3 IPC: borrowed handles time out automatically under kernel control, expired handles are rejected, and clients can recover by re-resolving or receiving fresh authority according to profile.
- Per-process isolation policy is now online for discovery: the kernel applies explicit process profiles before granting service-class or endpoint-class capabilities, so sandboxed tasks can be forced to rely on delegated authority instead of ambient discovery.

UEFI and ISO media attach a deterministic GPT/FAT32 QEMU NVMe image, discover class `0x01/0x08` through ECAM, map BAR0 as a 64-bit MMIO aperture, create broker-private admin SQ/CQ plus a 4 KiB Identify buffer, enable the controller with bounded `CSTS.RDY` polling, submit Identify Controller, create broker-private IO queues, read GPT and VBR sectors through the same IO queue, parse BPB geometry, reconstruct ASCII and Unicode LFN entries, traverse nested directories, and follow multi-cluster file chains. The write side remains broker-private: it creates a new LFN file in cluster `12`, extends `NVME.TXT` through cluster `13`, deletes `/REMOVE.ME` from cluster `14`, flushes the dirty FAT/data/directory sectors, and verifies persistence by read-back. It deliberately stops before NVMe block endpoints, filesystem delegation, caller-visible write authority, format authority, or commit authority; BIOS/disk media report unavailable.
- The `drs-nvme-rw` checkpoint deliberately skips redundant read-only NVMe publication rungs and turns the proven FAT32 driver into one scoped shell write authority. The broker mints a persistent read-write FAT32 capability for the shell principal, denies wrong-owner/stale/revoked use, routes shell-created files to the NVMe sidecar, records write/readback/audit/commit telemetry, and proves same-image persistence with two sequential QEMU boots. It still does not publish an NVMe block endpoint, grant format authority, create ambient filesystem paths, or mint any additional filesystem capabilities.
